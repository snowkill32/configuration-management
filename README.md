# Эмулятор оболочки: вариант 24

Практическая работа по конфигурационному управлению, вариант 24
из файла «УНБО-04-25.pdf», страницы 77-78. Реализация на Python,
без сторонних библиотек.

Выполнены этапы 1, 2 и 3 включительно. Команды `ls` и `cd`
остаются заглушками: их полноценная логика относится к этапу 4.

## Этап 1: REPL

Консольный интерфейс, приглашение с именем VFS, разбор команды
и аргументов по пробелам. `ls` и `cd` выводят имя и список аргументов.
`exit` завершает работу. Неизвестная команда и лишние аргументы
вызывают сообщение об ошибке; диалог продолжается.

Синтаксис: `ls [путь]`, `cd [путь]`, `exit`.
Кавычки и раскрытие переменных не обрабатываются: по условию
варианта используется простой разбор по пробелам.

## Запуск и проверка

Нужен Python 3.10 или новее. Сборка не требуется.
Из папки проекта:

```powershell
python src/main.py
python -m unittest discover -s tests -v
```

В Windows также можно выполнить `run.bat`.

## Этап 2: конфигурация

Параметры `--vfs` и `--script` задают путь VFS и стартового скрипта.
По умолчанию используется `examples/minimal.xml`, стартовый скрипт
не задан. Оба параметра выводятся при запуске.

```powershell
python src/main.py --vfs examples/minimal.xml --script examples/startup.txt
powershell -ExecutionPolicy Bypass -File scripts/test_config.ps1
powershell -ExecutionPolicy Bypass -File scripts/test_errors.ps1
```

Стартовый скрипт содержит по одной команде на строку. При выполнении
показываются приглашение, команда и ее вывод. На первой ошибке
исполнение прекращается с кодом 1. `exit` завершает приложение с
кодом 0. Если скрипт закончился без `exit`, запускается диалог.
Пустые строки допустимы. Скрипты `error_*.txt` демонстрируют ошибки
команд и аргументов. В отличие от интерактивного режима, строки
после ошибки в скрипте не выполняются.

Пример диалога:

```text
minimal:/$ ls
ls: аргументы = []
minimal:/$ cd /docs
cd: аргументы = ['/docs']
minimal:/$ unknown
Ошибка: неизвестная команда: unknown
minimal:/$ ls a b
Ошибка: ls: допустим один путь
minimal:/$ exit
```

## Основные функции

- `Shell(name, output, vfs)` задает имя, поток вывода и объект VFS.
- `Shell.execute(line)` разбирает и выполняет одну команду.
- `Shell.prompt` возвращает приглашение с именем VFS.
- `Shell.repl()` запускает цикл ввода.
- `Shell.run_script(path)` выполняет стартовый скрипт до первой ошибки.
- `parse_args()` читает параметры командной строки.
- `main()` является точкой входа.
- `load_vfs(path)` проверяет XML и создает VFS в памяти.
- `VFS(name, entries)` хранит имя и словарь виртуальной файловой системы.
- `add_node(element, parent, entries)` загружает узел и его потомков.
- `validate_node(element)` проверяет имя, тип и атрибуты узла.
- `file_data(element)` читает текст или декодирует base64.
- `VFS.describe()` показывает загруженные пути при запуске.

## Этап 3: виртуальная файловая система

XML загружается в словарь `VFS.entries`: ключ - абсолютный виртуальный
путь, значение - байты файла или `None` для каталога. Корень `/`
создается автоматически. Оболочка хранит загруженный объект `VFS`,
его имя используется в приглашении. При запуске показываются все
загруженные пути и размеры файлов, чтобы можно было проверить VFS.

XML только читается. Виртуальные файлы и каталоги на диск не
распаковываются; исходный XML не изменяется. Ошибки чтения,
поврежденный XML, повторяющиеся пути, неверные имена, неизвестные
элементы и некорректные данные base64 приводят к сообщению
`Ошибка загрузки VFS` и коду выхода 1.

Простой формат XML:

```xml
<vfs name="demo">
  <dir name="docs">
    <file name="readme.txt">Текст файла.</file>
    <file name="data.bin" encoding="base64">AAEC/w==</file>
  </dir>
</vfs>
```

`vfs` содержит обязательный атрибут `name`. Внутри него могут быть
элементы `dir` и `file`, также с атрибутом `name`. Имя узла не может
быть `.` или `..` и содержать `/` или обратный слеш. Для текстового файла
используется UTF-8; для двоичного указывается `encoding="base64"`.

Примеры VFS:

- `examples/minimal.xml`: только корень.
- `examples/files.xml`: несколько файлов, включая пустой и двоичный.
- `examples/deep.xml`: четыре вложенных каталога и файлы внутри.
- `examples/invalid.xml`: намеренно поврежденный XML для проверки ошибки.

Запуск вложенной VFS:

```powershell
python src/main.py --vfs examples/deep.xml --script examples/startup.txt
```

`examples/startup.txt` показывает успешные команды и `exit`.
`examples/demo_all.txt` показывает пути разных видов, пустую строку
и неизвестную команду. Он останавливается на ошибке, поэтому команда
`exit` после нее не выполняется. Файлы `error_unknown.txt`,
`error_arguments.txt`, `error_ls.txt` и `error_exit.txt` отдельно
демонстрируют все ошибки заглушек и команды завершения.

## Полная проверка

```powershell
python -m unittest discover -s tests -v
powershell -ExecutionPolicy Bypass -File scripts/test_config.ps1
powershell -ExecutionPolicy Bypass -File scripts/test_errors.ps1
powershell -ExecutionPolicy Bypass -File scripts/test_vfs.ps1
```

PowerShell-скрипты проверяют параметры запуска, стартовые скрипты,
три варианта VFS и ошибки загрузки. `test_vfs.ps1` также сравнивает
хеш XML до и после запуска. Тесты Python проверяют команды,
остановку на ошибке, декодирование двоичных данных и отсутствие
распаковки файлов на диск.

## Структура и история

`src/` содержит исходный код, `tests/` - тесты, `examples/` - XML и
команды для демонстрации, `scripts/` - проверки для Windows.
`run.bat` принимает те же параметры, что `python src/main.py`.

Этапы 1-3 сохранены в одном коммите `feat(shell)` с описанием изменений.
Историю можно посмотреть командой `git log --oneline`.
