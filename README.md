# Эмулятор оболочки: вариант 25

Практическая работа из «УНБО-04-25.pdf», страницы 80–82.
Реализованы этапы 1, 2 и 3. Python 3.10 или новее,
сторонние библиотеки и сборка не нужны.

## Запуск

Из папки проекта:

```bat
python src/main.py
python src/main.py --vfs examples/files.csv --script examples/startup.txt
python src/main.py --vfs examples/deep.csv --script examples/demo_all.txt
```

В Windows можно использовать `run.bat` с теми же параметрами.
Памятка с командами и объяснениями от первого лица: [Защита.md](Защита.md).

## Этап 1: ручной ввод

Консольная оболочка показывает имя VFS в приглашении.
Команды: `ls [путь]`, `cd [путь]`, `exit`.
`ls` и `cd` пока заглушки: показывают название и аргументы.
Настоящий просмотр папок и переход между ними относятся к этапу 4.

`shlex.split()` учитывает одинарные и двойные кавычки.
`ls "/my docs"` передает один аргумент `/my docs`; без кавычек
получатся два аргумента. Лишние пробелы и пустой ввод допустимы.
Неизвестная команда, лишние аргументы и незакрытые кавычки дают
сообщение об ошибке. При ручном вводе работа после ошибки продолжается.
`exit` завершает оболочку; Ctrl+C и конец ввода также завершают диалог.
Подстановка переменных не выполняется.

## Этап 2: настройки и файл команд

- `--vfs` — путь к CSV-файлу VFS. Теперь файл загружается и проверяется.
- `--script` — путь к стартовому текстовому файлу команд.
- `--help` — справка по параметрам.

Настройки выводятся при запуске. Без `--vfs` создается пустая VFS
с именем `vfs` в памяти. Без `--script` начинается ручной ввод.
Пути к файлам, содержащие пробелы, при запуске заключаются в кавычки.

В стартовом файле каждая строка — отдельная команда. Программа
показывает приглашение, команду и результат. При ошибке печатается
номер строки, ошибочная строка пропускается, выполнение продолжается.
После `exit` остальные строки не выполняются. Если файл заканчивается
без `exit`, начинается ручной ввод.

Коды завершения: 0 — нормальное завершение; 1 — ошибка загрузки VFS
или чтения файла команд; 2 — неверные параметры запуска (`argparse`).
Ошибка отдельной команды стартового файла сама по себе не дает код 1.

## Этап 3: VFS из CSV

CSV загружается целиком в словарь `VFS.entries` в памяти.
Ключ — абсолютный виртуальный путь, значение `None` — папка,
значение `bytes` — содержимое файла. Пустой файл хранится как `b""`.
Корень `/` создается автоматически. Виртуальные файлы на диск
не распаковываются, исходный CSV не изменяется.

Имя VFS берется из имени CSV без расширения. После загрузки показываются
пути и размеры файлов. Если в корне есть файл `/motd`, его текст UTF-8
выводится до выполнения команд. Файл `/docs/motd` приветствием не считается.
Если `/motd` отсутствует, программа просто продолжает запуск.

### Формат CSV

Обязательная первая строка: `path,type,encoding,data`.

```csv
path,type,encoding,data
/motd,file,utf-8,Добро пожаловать!
/docs,dir,,
/docs/readme.txt,file,utf-8,"Текст, содержащий запятую."
/docs/data.bin,file,base64,AAEC/w==
```

- `path` — полный путь, например `/docs/readme.txt`.
- `type` — `dir` для папки или `file` для файла.
- `encoding` — `utf-8` для текста, `base64` для двоичных данных.
- `data` — содержимое; у папок последние два поля пустые.

Каждая родительская папка описывается отдельной строкой.
Порядок строк не важен. Корень `/` отдельно указывать не надо.
CSV-кавычки нужны для текста с запятыми, переносами и кавычками.
Это правила формата CSV; кавычки в командах отдельно обрабатывает `shlex`.

Пути должны начинаться с `/`, без пустых частей, `.` и `..`.
Повторяющиеся пути, неизвестные типы и кодировки, неверный заголовок,
ошибочные данные base64, отсутствующие родители и нечитаемый CSV
приводят к сообщению «Ошибка загрузки VFS» и коду 1.

### Примеры

- `minimal.csv` — только корень, без `motd`.
- `files.csv` — текстовые, пустой и двоичный файлы, приветствие `/motd`.
- `deep.csv` — четыре вложенные папки, файлы и папка с пробелом в имени.
- `invalid.csv` — неправильный base64 для проверки ошибки загрузки.

Все примеры находятся в `examples/`.
`startup.txt` показывает успешные команды и выход.
`error_*.txt` показывают продолжение после разных ошибок.
`demo_all.txt` показывает все реализованные команды с аргументами
и без них, разные пути, кавычки, пробелы, пустую строку, ошибки и выход.
Он запускается с разными VFS. Строка после последнего `exit` не выполняется.

## Основные функции

- `parse_args()` — читает параметры запуска.
- `main()` — загружает VFS, выводит `motd`, создает оболочку и запускает команды.
- `Shell.__init__(name, output, vfs)` — сохраняет настройки и объект VFS.
- `Shell.prompt` — формирует приглашение с именем VFS.
- `Shell.execute(line)` — разбирает и выполняет одну команду.
- `Shell.repl()` — повторяет ручной ввод.
- `Shell.run_script(path)` — выполняет файл, пропуская ошибочные строки.
- `VFS.__init__(name, entries)` — сохраняет имя и словарь файлов и папок.
- `VFS.describe()` — формирует текстовый список загруженных путей.
- `VFS.motd()` — читает текст корневого файла `/motd` из памяти.
- `load_vfs(path)` — загружает CSV или создает VFS по умолчанию.
- `validate_path(path)` — проверяет виртуальный путь.
- `decode_data(encoding, data)` — получает байты из UTF-8 или base64.
- `add_record(row, entries)` — проверяет и добавляет одну строку CSV.
- `validate_parents(entries)` — проверяет наличие родительских папок.

## Проверка

```bat
python -m unittest discover -s tests -v
powershell -ExecutionPolicy Bypass -File scripts/test_config.ps1
powershell -ExecutionPolicy Bypass -File scripts/test_errors.ps1
powershell -ExecutionPolicy Bypass -File scripts/test_vfs.ps1
```

35 тестов Python проверяют команды, кавычки, параметры, загрузку CSV,
приветствие, ошибки, вложенные папки и работу в памяти.
Отдельно проверяется, что изменение словаря не меняет CSV и не создает
файлов на диске; VFS по умолчанию не читает файлов.

`test_config.ps1` и `test_vfs.ps1` запускают минимальную, обычную
и вложенную VFS. Оба проверяют параметры `--vfs` и `--script`.
`test_vfs.ps1` сравнивает хеш CSV до и после запуска.
`test_errors.ps1` проверяет ошибки команд и отсутствие стартового файла.

## Проверка требований третьего этапа

| Пункт | Что реализовано и чем проверяется |
|---|---|
| 1. Работа в памяти | Словарь `entries`, тест `test_memory_only`, сравнение хешей CSV. |
| 2. CSV, двоичные данные, вложенность | Полные пути, UTF-8/base64, `files.csv`, `deep.csv`, тесты загрузки. |
| 3. Ошибки загрузки | Сообщение и код 1, тесты отсутствующего и неправильного CSV. |
| 4. Приветствие `motd` | Только корневой файл, вывод до команд, проверки наличия и отсутствия. |
| 5. VFS по умолчанию | `load_vfs(None)`, пустой корень в памяти, тест запрета чтения диска. |
| 6. Несколько скриптов ОС | `test_config.ps1` и `test_vfs.ps1`, каждый запускает три вида VFS. |
| 7. Стартовый скрипт | `demo_all.txt`, проверка ошибок, путей, кавычек и остановки после `exit`. |
| 8. Коммиты | Отдельные коммиты загрузчика, подключения к запуску и проверок с документацией. |

Функциональные требования этапов 1–3 реализованы. Этапы 4 и 5 еще не выполнены.

## Общие требования и замечания

Есть README, .gitignore, src, tests и run.bat. Коммиты оформлены
в стиле Conventional/Scoped Commits. Архивы, бинарные файлы, кэш Python
и артефакты сборки не добавлены в репозиторий.
Проверены размеры файлов и строк, длина функций, число аргументов,
сложность функций и числовые литералы в сравнениях.

Итог проверки третьего этапа: 35 тестов и три скрипта Windows прошли.
Самый большой файл — 614 строк, строка Python — не более 80 символов,
функция — не более 24 строк, параметров — не более 4.
Оценка сложности по ветвлениям AST — не более 7 при лимите 10.

Остаются два замечания к оформлению по методичке:

- Пункт К1: docstring в коде отсутствуют. Ранее они были удалены
  по просьбе оставить только редкие обычные комментарии.
- Старые этапы 1 и 2 не разделены отдельными коммитами в текущей истории.
  Третий этап сохраняется отдельными последовательными коммитами.

Поэтому функциональную готовность этапов 1–3 не следует путать
с полным соответствием всем общим требованиям оформления.
