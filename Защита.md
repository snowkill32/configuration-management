## 5. Показываю код первого этапа

Открываю `src/shell.py`. Показываю `__init__()`.

Говорю:

> При создании оболочки задаются имя, место вывода сообщений и признак

Показываю `prompt` и строку `return f"{self.name}:/$ "`.

```python
parts = shlex.split(line)

    return
command, *args = parts
```

Говорю:

> `shlex.split()` разбирает строку с учетом кавычек. Пустой ввод
> пропускается. Первое слово сохраняется в `command`, остальные
> слова попадают в список `args`.

Показываю условия для `exit`, `ls`, `cd` и последний `else`.

Говорю:

> Здесь выбирается действие. Для `ls` и `cd` проверяется число аргументов.
> Для `exit` проверяется отсутствие аргументов. Неправильная команда
> или аргументы вызывают ошибку `ValueError` через `raise`.

Показываю `repl()`:

```python
while self.running:
    try:
        line = input(self.prompt)
        self.execute(line)
```

Говорю:

> Цикл получает строку с клавиатуры и передает ее в `execute()`.
> Ниже `except` перехватывает ошибки и выводит сообщение.
> Поэтому ошибка команды не прерывает ручной ввод.

Показываю `self.running = False` в обработке `exit`.

Говорю:

> После `exit` признак работы становится `False`, и цикл заканчивается.

## 8. Показываю настройки в коде второго этапа

Открываю `src/main.py`. Показываю `parse_args()`.

Говорю:

> Параметры запуска читает готовый модуль `argparse`.
> Через `add_argument()` задаются параметры `--vfs` и `--script`.
> `type=Path` превращает текст параметра в объект пути.
> Если `--vfs` не указан, его значение будет `None`.
> `help` содержит пояснение для справки `--help`.

Показываю `return parser.parse_args()`.

Говорю:

> Эта строка читает параметры запуска и возвращает результат.

Показываю начало `main()`:

```python
args = parse_args()
print(f"VFS: {args.vfs or 'по умолчанию (в памяти)'}")
print(f"Стартовый скрипт: {args.script or 'не задан'}")
```

Говорю:

> Результат чтения настроек сохраняется в `args`. Затем настройки
> выводятся на экран. Затем загружается VFS и создается оболочка.
> Имя файла без расширения становится именем VFS при загрузке.
> Если стартовый файл не указан, вместо пути показывается «не задан».

Показываю:

```python
if args.script and not shell.run_script(args.script):
    return 1
shell.repl()
return 0
```

Говорю:

> Если путь к файлу команд указан, вызывается `run_script()`.
> Если сам файл прочитать не удалось, метод возвращает `False`,
> а `main()` возвращает код ошибки `1`. Иначе вызывается ручной ввод.
> Если в файле уже был `exit`, цикл ручного ввода не начинается.

Запоминаю условие для себя: `and` не вызывает правую часть,
если `args.script` равен `None`. `not` превращает `False` в `True`.

## 9. Показываю выполнение файла в коде

Открываю `run_script()` в `src/shell.py`. Показываю:

```python
lines = Path(path).read_text(encoding="utf-8-sig").splitlines()
```

Говорю:

> Читаю текст файла и делю его на строки. `utf-8-sig` также учитывает
> служебную отметку BOM в начале некоторых текстовых файлов.

Показываю:

```python
for number, line in enumerate(lines, 1):
    print(self.prompt + line, file=self.output)
    try:
        self.execute(line)
    except ValueError as error:
        print(f"Ошибка в строке {number}: {error}", file=self.output)
        continue
```

Говорю:

> `enumerate()` дает номер строки, начиная с единицы, и саму строку.
> Команда сначала показывается, затем передается в `execute()`.
> Это тот же метод, что используется при ручном вводе.
> При ошибке показывается сообщение, а `continue` переводит цикл
> к следующей строке.

Показываю проверку `if not self.running: break` и `return True`.

Говорю:

> После `exit` перебор строк прекращается. Это нормальное завершение,
> поэтому метод возвращает `True`. Ошибки отдельных команд пропускаются
> и не делают результат метода `False`.

Показываю `except (OSError, UnicodeError)` в начале метода.

Говорю:

> Если сам файл не найден или его текст не читается, выполнять команды
> невозможно. В этом случае показывается сообщение и возвращается `False`.

## Если задают вопросы по Python

**Если спрашивают про `self`, говорю:**

> `self` — объект оболочки, с которым работает метод. Через него методы
> обращаются к имени, месту вывода и признаку работы этого объекта.
> При вызове `shell.repl()` Python передает объект `shell` как `self`.

**Если спрашивают про `sys.stdout`, говорю:**

> Это стандартный поток вывода. При обычном запуске текст через него
> отображается в консоли.

**Если спрашивают про `file=self.output`, говорю:**

> Этот параметр задает, куда `print()` выводит текст. Обычно это консоль,
> а в тестах вывод сохраняется в памяти для проверки.

**Если спрашивают про `raise`, `try` и `except`, говорю:**

> `raise` создает ошибку. Внутри `try` выполняется код, который может
> вызвать ошибку. `except` перехватывает ее и позволяет вывести сообщение.

**Если спрашивают про `return`, `break` и `continue`, говорю:**

> `return` завершает всю функцию или метод и возвращает результат.
> `break` прекращает цикл. `continue` переходит к следующему повторению цикла.

**Если спрашивают про последние строки `main.py`, говорю:**

> Проверка `__name__ == "__main__"` запускает `main()`, когда этот файл
> запущен напрямую. `sys.exit(main())` получает результат `main()`
> и передает его операционной системе как код завершения.

**Если спрашивают про коды завершения, говорю:**

> В программе `0` означает нормальное завершение. `1` означает,
> что VFS или файл команд не удалось загрузить. Код `2` возвращает `argparse`
> при неверных параметрах запуска. Ошибки команд внутри файла
> показываются и пропускаются, поэтому сами по себе не дают код `1`.

**Если спрашивают, какие библиотеки надо установить, говорю:**

> Достаточно Python 3.10 или новее. Все используемые модули входят
> в стандартную библиотеку Python.
