## Показываю пятый этап: cp и mv

Перед показом выхожу через `exit` и запускаю чистую VFS из Windows:

```bat
python src/main.py --vfs examples/deep.csv
```

Внутри оболочки ввожу по очереди:

```text
cp /docs/notes.txt /copy.txt
ls /
rev /copy.txt
rev /docs/notes.txt
mv /copy.txt /renamed.txt
ls /
mv /renamed.txt "/my docs"
ls "/my docs"
```

Говорю:

> `cp` создаёт копию. Оригинальный файл остаётся на месте, содержимое
> совпадает. `mv` переносит запись: старое имя исчезает, новое появляется.
> Если передаю существующую папку, файл помещается внутрь неё.
> Успешные `cp` и `mv` ничего не печатают, результат проверяю через `ls`.

Ввожу:

```text
cp -r /docs /backup
ls /backup/projects/demo/src
cd /backup/projects/demo/src
mv /backup /renamed-backup
pwd
rev main.txt
cd /
```

Показываю `main.txt`, новый путь `/renamed-backup/projects/demo/src`
и перевёрнутый текст. Говорю:

> `-r` означает копирование папки вместе со всеми вложенными записями.
> `mv` переносит папку целиком. Если переносится моя текущая папка
> или её родитель, программа обновляет `cwd`, и относительные пути работают.

Ввожу:

```text
cp /motd "/my docs/renamed.txt"
rev "/my docs/renamed.txt"
cp /docs/notes.txt "/my docs/a b.txt"
mv "/my docs/a b.txt" "/my docs/renamed.txt"
rev "/my docs/renamed.txt"
```

Говорю:

> Кавычки объединяют путь с пробелами в один аргумент.
> Если назначение — существующий файл, его содержимое перезаписывается.
> Для копирования и переноса текст не декодируется: переносятся байты,
> поэтому двоичные и пустые файлы также поддерживаются.

Ввожу по очереди:

```text
cp
mv /docs
cp /missing /new.txt
cp /docs /copy-dir
cp /docs/notes.txt /missing/new.txt
cp /docs/notes.txt /docs/notes.txt
mv /docs /docs/projects
```

Говорю:

> Нужны два пути: откуда и куда. Источник и родитель назначения должны
> существовать. Для копирования папки нужен `-r`. Нельзя скопировать файл
> в него самого или перенести папку внутрь себя. При ошибке данные не меняются.
> Папка не заменяет файл, а файл — папку. `mv` также не заменяет непустую
> папку с совпадающим именем. `cp -r` может объединять папки.
> Корень нельзя перемещать или копировать; другие флаги я не реализовывал.

Показываю код `cp_command()`, `mv_command()` и `two_paths()` в `shell.py`.

Говорю:

> `two_paths()` проверяет число аргументов. Для `cp` сначала отделяется
> флаг `-r`, затем вызывается метод VFS. Для `mv` вызывается перенос,
> и возвращённый текущий путь сохраняется в `self.cwd`.

В `vfs.py` показываю `destination_path()`, `transfer_entries()`,
`check_replacements()`, `copy()` и `move()`.

Говорю:

> Сначала определяется назначение. У вложенных записей заменяется начало
> пути: `/docs/notes.txt` становится `/backup/notes.txt`.
> Все назначения проверяются до изменения словаря, чтобы ошибка
> не оставляла половину результата. `copy()` добавляет новые записи,
> `move()` ещё удаляет старые. Файлы Windows этими методами не открываются.

Внутри ввожу `ls /`, затем `exit`. Говорю:

## Запоминаю ответы на вопросы по Python

Если спрашивают про `self`, говорю:

> Это объект оболочки, с которым работает метод. При `shell.repl()`
> Python передаёт объект `shell` как `self`. Через него получаю данные объекта.

Если спрашивают про `sys.stdout` и `file=self.output`, говорю:

> `stdout` — стандартный поток вывода, обычно консоль. Параметр `file`
> у `print()` задаёт место вывода. В тестах вместо консоли используется память.

Если спрашивают про `return`, `break`, `continue`, говорю:

> `return` выходит из функции, `break` выходит из цикла,
> `continue` переходит к следующему повторению цикла.

Если спрашивают про `try`, `except`, `raise`, говорю:

> В `try` выполняется код, `raise` создаёт ошибку, `except` перехватывает её.

Если спрашивают про конец `main.py`, говорю:

> Условие `__name__ == "__main__"` запускает функцию при прямом запуске файла.
> `sys.exit(main())` передаёт результат функции как код завершения программе Windows.

Если спрашивают про коды завершения, говорю:

> 0 — нормальное завершение, 1 — ошибка загрузки VFS или чтения файла команд,
